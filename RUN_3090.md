# Running the Precomputed-KV-Cache Quantization Experiment on an RTX 3090

This guide covers the **headline RGB-only experiment** (RGB ×
C0/C1/C2/C3 × K∈{1,3,5}) on a single **RTX 3090 (24 GB VRAM, Ampere sm_86)**.

> **Read this first — the v1→v2 remediation changed three things that invalidated
> the old run:**
> 1. **bfloat16, not float16.** Qwen2.5 is bf16-native; fp16 overflowed its KV
>    values and produced NaN→token-0 corruption (`Def!ensive! Coordinator`). The
>    model, the build prefill, and the C1 "reference" cache are all bf16 now.
> 2. **`precompute_mode: standard_causal` (default).** Chunks are concatenated and
>    prefilled with ONE stock causal pass — in-distribution, needs no SFT. The old
>    `reordered` TurboRAG scheme is kept only as a labelled secondary baseline.
> 3. **A Stage-0 gate** runs C0+C1 first and halts the pipeline unless the baseline
>    is trustworthy (C1 ≈ C0, zero non-finite logits, degeneracy < 2%).

> Note: the RTX 3090 has **24 GB** of VRAM. Debug on **Qwen2.5-3B** (the config
> default); switch `model.name` to 7B only for the final run.

## TL;DR commands

```bash
export SCRATCH_DIR="${SCRATCH_DIR:-/scratch/${USER}/kv_quant}"
export HF_HOME="${HF_HOME:-/scratch/${USER}/hf_cache}"
export TRANSFORMERS_CACHE="${TRANSFORMERS_CACHE:-${HF_HOME}}"
export HF_DATASETS_CACHE="${HF_DATASETS_CACHE:-${HF_HOME}/datasets}"

# Headline run: RGB-only, bf16, standard_causal — entirely config-driven.
# (configs/full_experiment.yaml already sets rgb=200, nq_open=0, hotpotqa=0,
#  wiki_docs.num_docs=0.) The Stage-0 gate runs automatically before C2/C3.
python src/run_experiment.py --config configs/full_experiment.yaml

# Just the gate (sanity-check the baseline before committing GPU hours):
python src/run_experiment.py --config configs/full_experiment.yaml --stages build stage0

# Optional secondary: add HotpotQA back (set its num_examples > 0), or run the
# legacy reordered baseline by setting precompute_mode: reordered in the YAML.
```

Every value is also a CLI flag — **no source edits are required**. The resolved
run config (including `dtype`, `precompute_mode`, `wiki_pages`) is written to
`$SCRATCH_DIR/results/$MODEL_SLUG/config.json` and echoed into every summary row
and the `logs_*.txt`.

> **standard_causal needs almost no disk.** It prefills caches at query time, so
> `chunk_cache.py` runs with `--index_only` (automatically) and writes ONLY the
> retrieval index — the large per-chunk `.pt` files below are NOT produced. The
> disk table applies only to the legacy `reordered` mode.

## The binding constraint is DISK, not VRAM

KV-cache geometry for `Qwen2.5-3B-Instruct` (36 layers, 2 KV heads, head_dim 128):

| Precision | Bytes / token | Relative |
|---|---|---|
| FP16 | 36.0 KB | 1.00× |
| INT8 | 19.1 KB | 0.53× |
| INT4 |  9.6 KB | 0.27× |
| **All three (C1+C2+C3)** | **64.7 KB** | — |

Running C0–C3 requires **all three** precision files per chunk.

### Disk estimate by `--wiki_pages` (all three precisions)

| `--wiki_pages` | Wiki KV cache | + HotpotQA (~18 GB) + RGB (~50–100 GB) | Total to provision |
|---|---|---|---|
| 1,000  |   9 GB | + ~70 GB | **~80 GB** |
| 5,000  |  46 GB | + ~70 GB | **~115 GB** |
| 10,000 |  92 GB | + ~70 GB | **~160–210 GB** |
| 15,000 | 138 GB | + ~70 GB | **~210–260 GB** |
| 25,000 | 230 GB | + ~70 GB | **~300–350 GB** |

> RGB documents are long web snippets (5 positive + 15 negative per question);
> their KV caches dominate after wiki. If disk is tight, lower `--num_rgb_examples`
> or `--wiki_pages` first. The KV caches are **intermediate** — delete
> `$SCRATCH_DIR/chunk_kvcache/$MODEL_SLUG` after the eval+analyze stages finish.

**Storage levers**
- Build only the precisions you need: `--conditions C0 C1` → FP16 only (≈0.54× disk).
- The `--precisions` filter is applied automatically from `--conditions`.
- Put `kvcache_dir` on **local NVMe**. The eval stage re-reads chunk caches once
  per (example × K × condition), so network/HDD storage will dominate wall time.

## VRAM budget (peak ≈ 10 GB of 24 GB — comfortable)

| Component | VRAM |
|---|---|
| Qwen2.5-3B (bfloat16) | ~6.2 GB |
| HHEM-2.1-Open (flan-t5-base) | ~1.0 GB |
| DeBERTa-v3-large NLI | ~1.7 GB |
| bge-small embedder | ~0.4 GB |
| Stitched KV cache @ K=5 (~2.6k tok) | ~0.1 GB |
| **Peak** | **~10 GB** |

No OOM risk. You have headroom to raise scorer batch sizes:
`evaluation.hhem_batch_size` / `nli_batch_size` → **32–64** (set in
`configs/full_experiment.yaml`).

**bfloat16 is required (ROOT CAUSE 1).** Qwen2.5 is trained in bf16; its KV
values routinely exceed the float16 max (~65504), so casting the cache to fp16
overflows to ±Inf and the next softmax/argmax yields NaN → token 0 (`!`). The
3090 (Ampere) supports bf16 natively. The model, the build prefill, the C1
reference cache, and the INT8/INT4 dequant targets are all bf16 now; a NaN/Inf
logit guard aborts and counts any residual corruption (a valid run reports zero).

## Runtime estimate (`--wiki_pages 10000`, 200 examples each)

Headline RGB-only run (`standard_causal`, 200 examples, C0–C3, K∈{1,3,5}):

| Stage  | Work | Est. time |
|---|---|---|
| build  | embed RGB corpus + build index (no per-chunk KV caches) | ~5–15 min |
| stage0 | C0+C1 on 50 examples + gate check | ~10–20 min |
| eval   | 1 ds × 3 K × 4 cond × 200 = 2,400 generations + HHEM/NLI | ~1.5–3 h |
| calib  | HHEM vs NLI correlation on a variance-bearing 300-sample mix | ~5 min |
| analyze + tables | McNemar (H1) + noise slope (H3) + figures (CPU) | <1 min |
| **Total** | | **~2–3.5 h** |

In `standard_causal` each query does one stock causal prefill over its
concatenated chunks (normal RoPE/causal mask) — in-distribution and cheaper than
the legacy `reordered` path, which re-rotated the full key sequence every decode
step (O(N²)) and was OOD without SFT.

## Bottlenecks & mitigations

1. **Stage-0 gate (do this first)** — if C1 is not ≈ C0, or any non-finite logits
   appear, the baseline is broken; fix dtype/precompute_mode before spending GPU
   hours on C2/C3. The gate halts the pipeline automatically.
2. **NQ-Open is dropped** for the headline run — a random DPR subset has poor recall
   for NQ questions (a retrieval-coverage confound) and the wiki corpus was the
   ~92 GB disk bottleneck. Re-enable only with a proper full DPR index
   (`wiki_docs.num_docs` large + `nq_open.num_examples > 0`); that path uses the
   `reordered`-style per-chunk caches and the disk table above.
3. **HHEM/NLI 512-token window** — with `faithfulness_mode: full_context`, long
   concatenated contexts at K=5 are truncated by the scorer. `per_chunk_max`
   avoids this but is lenient and can mask H2. **Run both and report.**
4. **Disk (legacy `reordered` mode only)** — eval re-loads each chunk's `.pt` per
   example/K/condition; provision per the table above. `standard_causal` does not
   write these files.
